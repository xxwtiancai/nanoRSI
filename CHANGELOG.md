- Add the counterfactual challenger to the acceptance gate (ADOPTION item 28, from the CHASE entry): with `[evaluator] counterfactual_enabled = true`, a candidate that clears the primary strict-improvement gate is re-scored together with its freshly measured parent on the evaluator's `counterfactual` panel — validity-preserving variants of the minimal task set authored as task-domain knowledge in the workspace (schema 2: manifest tasks with the new optional `counterfactual` split in their own groups; schema 1: an evaluator split of the same name). The second stage applies the same gate configuration; a gain that vanishes there is recorded with decision `shortcut`, consumes its attempt, never promotes, enters the `rejected_recent` memory, and is excluded from population ranking. Counterfactual evaluations are budgeted search episodes. Fixture validation: an exact-statement hardcoding candidate passes the primary gate and is caught (1/1 injected leaky candidates) while the honest keyword policy survives, and a primary-rejected candidate pays no challenge cost. The `harness-fixture` starter ships the challenger enabled; the mechanism's live-model catch rate is not yet measured. Core gains `src/nanorsi/challenge.py`, and a disabled challenger is excluded from the comparison identity so historical hashes are unchanged.
- Close the live half of the rejected-edit memory question (ADOPTION item 14) with an honest null: `examples/results/rejected-memory-ab/` runs the OpenEvolve function-minimization task with GLM-5.3-Flash in two arms (`rejected_recent` on vs off, five attempts each). Neither arm produced an identical or near-identical (Jaccard ≥ 0.6) repeat proposal — the hypothesized failure mode did not occur at this scale, so the memory's trigger never fired; both arms still evolved (candidates 0.9944/0.9997 vs baseline 0.9418). The memory stays on by default as a zero-observed-cost safeguard, and `[proposer] rejected_memory = false` ships as a per-workspace toggle (boolean-validated, with tests).
- Add a fixture-poisoning red team (ADOPTION item 31, from the "Trusting Trust, revisited" entry): four adversarial scenarios with honestly asserted outcomes. Candidates touching protected paths are rejected by the surface policy; an evaluator poisoned **before** baseline lets a token candidate through the strict-improvement gate — no existing control catches it, because the evaluator is inside the trust boundary by design (the finding is published as such); swapping the evaluator after baseline is blocked by the frozen-contract guard in both directions, so poisoning can neither enter nor leave silently; and the audit's expected-answer leakage scan now covers the **whole mutable surface** (every allow-patterned text file, ≤64 KB, root-relative paths) instead of only the skills directory.
- Add a rejected-edit memory (ADOPTION item 14): the proposal context now carries `rejected_recent`, bounded summaries (attempt id, decision, gate/hypothesis reasons capped at 200 characters, changed paths) of the last five rejected, failed or no-op proposals — metrics, diffs and artifacts never leak into the prompt. Fixture controls measure the plumbing: a memoryless scripted proposer repeated the identical rejected edit on every subsequent attempt (2/2 repeats), a memory-aware one switched after the first rejection (0/2 repeats); the real-model effect on repeat-proposal rate is an open live question.
- Publish `examples/results/glm53-real-tasks/`: two further upstream evaluation tasks run with **GLM-5.3 (full tier)**. (1) ShinkaEvolve's headless sine approximation (Apache-2.0, arXiv 2509.19349 task family): serial loop evolved `return x` into a degree-13 Taylor polynomial — final score on a denser held-out grid **0.1049 → 0.999963** (RMSE 1.347 → 3.98e-06), five model calls, blocked-sine anti-cheating check preserved. (2) OpenEvolve's K-Module configuration problem (5⁴ hidden target, count-only feedback): **population search with crossover 0/4 → 4/4 (score 1.0)** in eight attempts and eight model calls; honestly noted that the winner was a direct first-generation candidate, not a crossover product. Both audits clean, verify passing, failures and no-ops retained.
- Harden the live-model loop against real provider output, driven by running an actual upstream task end to end: the skills/program runner now retries a model call exactly once when the action content fails strict JSON parsing (recorded in usage), and strips a single outer markdown fence before strict parsing; candidate diffs apply through a bounded git-native repair ladder (`--recount`, then `--recount -C1`) that repairs miscounted and lightly drifted model-authored hunks while still rejecting hallucinated context; diff path extraction falls back to `+++ b/` lines for header-less diffs. Tests cover the retry, the fence envelope, the repair ladder and the path fallback.
- Publish `examples/results/openevolve-fnmin/`: a complete evaluation task ported verbatim from OpenEvolve (Apache-2.0, attribution retained) and run on nanoRSI with GLM-5.3-Flash. On the frozen unseen-seed test panel the evolved program scored 0.9960 vs the upstream initial program's 0.9418 (average distance to the known optimum 0.175 → 0.013; average value −1.4912 → −1.5184 against the true minimum −1.519). Five model calls / 11,067 tokens; rate-limit and corrupt-diff failures retained; two sub-gate micro-improvements honestly rejected; audit clean.
- Refocus the project mission on two tracks under one name: a minimal, runnable RSI implementation validated on minimal tasks with frozen/uniform/random controls, and a daily RSI research radar; update the charter and both READMEs accordingly.
- Add the radar log `docs/research/industry-rsi/RADAR.md` with a fixed daily-entry format, and document it in `FORMAT.md`. Days without qualified findings are logged with their searched scope and gaps.
- The daily research sweep now explicitly covers arXiv listings, company research pages, domestic and international university labs, conference and journal outputs, high-star GitHub RSI projects, and authoritative media leads that must trace back to original sources before catalogue inclusion.
- Add a per-revision evidence ledger (`src/nanorsi/evidence.py`): every `baseline`, `step`, `final-test` and `report` writes `reports/evidence.jsonl` and `reports/evidence.md`, combining each proposal's hypothesis, the candidate diff with per-file line stats, redacted per-case evaluator outcomes for the parent and candidate panels (task/group/repeat/score/status only), the gate decision with reason, and a sha256 integrity flag for every referenced run artifact. Failed and no-op attempts are included; the ledger is a derived read-only view and does not feed selection. The architecture inventory and specification gain the new core module; core size remains far below the 5,000-line ceiling.
- Add `nanorsi audit` (`src/nanorsi/audit.py`), a fresh-session skill audit for accepted generations: expected-answer leakage in `target/agent/skills/**` against the task manifest, silent bypass of executable skills (declared `run.py` never appearing in any `skill_script_invoked` trace event across the evaluation panel), and declared-but-unloaded names; markdown-only skills are reported as always-in-context rather than guessed at. Fixture tests inject one leaky-uninvoked skill and one invoked clean skill, measuring a 2/2 injected-defect catch rate with zero false blocks on the four clean skills. Read-only: the audit feeds no gate or selection.
- Add `tests/test_invariants.py`: basic property and invariant tests covering surface-policy enforcement (protected paths win even when re-included in the allow list; deny can only shrink the allowed set), gate decisions (ties never accepted, exact minimum-improvement boundary, monotonicity, minimize/maximize role-swap symmetry, failed constraints inconclusive, held-out regression rejection), search-episode reservation arithmetic, a no-change identity invariant (an empty proposal changes nothing but the attempt record) and repeated-evaluation determinism. The invariant-test pattern is an idea-level borrowing from open RSI projects that ship no unit tests themselves.
- Add `examples/smoke/run_smoke.py`, a one-command offline smoke experiment for newcomers: builds a CPU fixture workspace and narrates baseline → gated search (three accepted checkpoint updates, 0.0 → 0.25 → 0.5 → 0.75) → freeze → unseen final test (0.0 vs 0.75) → audit → evidence ledger. No API key, no network.
- Add `docs/RSI_MINIMAL.md` (+ zh-CN): a five-minute definition of bounded RSI, the seven-mechanism minimal set mapped to this repository, and an honest account of what OpenRSI (CC BY-NC: four operators, Gym/Evo/ERL decomposition, smoke validation, no unit tests) and MetaRSI/RSI-Harness (no license file: D/θ/H triple, seven-step kernel, five-slot scaffold, identity/coverage invariants, control battery) contribute at idea level — no upstream code is copied or reproduced.
- Publish the live skills study `examples/results/live-skills-frozen-selfuse/` (ADOPTION item 7, comparison half): two arms, seed 0, GLM-5.3-Flash, three attempts each. Evolved skills transferred to unseen tasks (0/3 → 2/3 on the frozen test panel in both arms); self-use showed no advantage over the frozen proposer (identical final panels, smaller accepted validation gain). The sort-variant task failed in every condition and is retained as a known counterexample. The audit found zero expected-answer leakage and zero silent-bypass scripts; all attempts including no-ops and tie-rejections are in the published evidence ledgers. 190 model calls / 138,415 tokens total; cost unknown (no provider cost field).

- Distinguish completed final outcomes from complete training budgets, retain failed-attempt work and report both all-measured and matched-budget paired effects with descriptive and family-adjusted uncertainty.
- Publish the complete handwritten-digit confirmation panel: 120 runs, 720 completed training rounds, 676 accepted and 44 rejected candidates, no failed attempts, and verified matched actual budgets. Include all four controls, validation-only pilot records, per-case outcomes, curricula, training receipts and checkpoints in an unsigned public extract without HMAC keys.
- Add bilingual study guides and paired results to both READMEs while preserving the v0.4.0 CPU and live-model history.

On the custom UCI/scikit-learn digits split, mean self-use minus frozen test accuracy was +3.654 pp for SFT (10/10 seeds positive), +8.187 pp for REINFORCE (9/10), and +2.527 pp for LoRA (8/10). Only REINFORCE met the predeclared observed-mean ≥5 pp target with a positive nominal Bonferroni-adjusted bootstrap lower bound; SFT and LoRA did not. This does not establish a true gain ≥5 pp. REINFORCE nevertheless trailed uniform sampling by 8.764 pp, and LoRA by 0.824 pp. SFT's test error fell from 10.16% to 6.51%, a 35.95% relative error reduction, equivalent to +3.65 pp accuracy. These results concern one fixed split and small linear models, not official benchmark performance or LLM fine-tuning. See the [complete results and evidence limits](examples/results/recursive-digits-v0.4.1/README.md).

The verified CPU panel completed 18 runs and 54 training rounds, with 20 accepted and 34 rejected candidates. Held-out mean accuracy rose from 46.11% to 84.44–86.39% across method/control groups on overlapping synthetic clusters. Self-use comparisons were mixed: one positive, one negative and seven ties. These teaching-scale results are not LLM fine-tuning, general benchmark performance or proof of general recursive self-improvement.

The live study used 43 GLM-5.3-Flash requests and 87,812 tokens. Five four-case demonstrations went from 1/4 to 4/4; the single batch-skill task went from 0/1 to 1/1. Recursive and frozen proposers tied on the final panel. A known parsing defect remains in the remote demo's measured generated candidate; see the [complete evidence and counterexample](examples/results/v0.4.0/README.md).
