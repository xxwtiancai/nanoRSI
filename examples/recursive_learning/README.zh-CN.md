# 递归复用检查点能带来额外收益吗？

[English](README.md) · [v0.4.1 完整结果与证据](../results/recursive-digits-v0.4.1/README.md)

这个可选数值实验比较 **self-use 减去 frozen 改进器的表现**，将递归复用的额外收益与普通“初始模型训练后变好”区分开。它通过 nanoRSI 的常规搜索、冻结和最终测试命令，在手写数字图像上真正执行 SFT、采样奖励 REINFORCE 和秩为 4 的 LoRA 更新。模型是小型线性分类器，不是预训练 LLM 微调，也不代表通用 RSI 已得到验证。

## 实测结果

确认实验使用实现 `7809e7924bf806272b721fb829ef689db0263718`，完成全部 **120 次实验和 720 轮训练**：676 个候选被接受、44 个被拒绝，没有失败尝试。所有实验先冻结再测试，实际更新数、采样数和评分工作量均匹配计划。因此，全体已测量结果与完整样本结果一致。

| 方法 | Frozen | Self-use | Uniform | Random | Self-use − frozen | 正向种子数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| SFT | 89.835% | 93.489% | 92.582% | 92.390% | +3.654 个百分点 | 10/10 |
| REINFORCE | 19.286% | 27.473% | 36.236% | 27.005% | +8.187 个百分点 | 9/10 |
| LoRA | 79.533% | 82.060% | 82.885% | 83.736% | +2.527 个百分点 | 8/10 |

表中为选中检查点的平均最终测试准确率。三个主要 self-use − frozen 比较，经 Bonferroni 校正后名义置信度为 98.333% 的 bootstrap 区间分别为：SFT **[2.198, 5.192]**、REINFORCE **[1.071, 13.462]**、LoRA **[0.549, 4.423] 个百分点**。只有 REINFORCE 达到了预先声明的“观测平均提升 ≥5 个百分点且校正下界为正”目标；SFT 和 LoRA 未达到。这不等于证明真实增益至少有 5 个百分点。REINFORCE 仍比 uniform 低 8.764 个百分点。LoRA 比 uniform 低 0.824 个百分点，其描述性 95% 区间包含零。SFT 比 uniform 高 0.907 个百分点、比 random 高 1.099 个百分点；这些均为描述性的次要比较。

相比 frozen 优先级，SFT 的平均测试错误率从 10.16% 降到 6.51%，即**相对错误率下降 35.95%**，对应**准确率提高 3.65 个百分点**。这个实测效果限于下述固定数据划分与训练设置。[完整结果包](../results/recursive-digits-v0.4.1/README.md)列出了所有比较、区间和证据文件。

## 复现

此可选适配器需要 Python 3.11+、Git、nanoRSI 和已有的 NumPy 安装。nanoRSI 包与内核仍没有第三方运行时依赖。不需要模型 API key、GPU、重新下载数据或安装 scikit-learn；已注明来源的约 57KB 数据文件随仓库提供。

先检查准备运行实验的 Python 环境：

```bash
python -c "import sys, numpy, nanorsi; print(sys.version); print(numpy.__version__)"
```

如果缺少 NumPy，只需在这个可选实验环境中安装；下面的版本与公开实验一致：

```bash
python -m pip install numpy==2.3.3
```

```bash
# 在仓库根目录执行，当前解释器需要能使用 nanoRSI 和 NumPy：
python examples/recursive_learning/run.py ./digits-study --phase search --workers 2
# 所有计划内实验必须已经冻结；以下步骤才首次使用测试集：
python examples/recursive_learning/run.py ./digits-study --phase final --workers 2
```

默认面板为**三种方法 × 十个初始化/训练种子（10–19）× 四种策略 = 120 次实验**。搜索阶段的输出目录必须尚不存在。`--phase final` 读取保存的计划，不会默默创建新研究；`--phase all` 会按相同顺序执行这两个阶段。请在仓库检出目录中运行，并让 `python` 与 `nanorsi` 使用同一个 Python 3.11+ 环境。公开实验使用 Python 3.13、NumPy 2.3.3；保存的计划记录了准确的实现版本与设置。每次实验保留常规工作区和已核验日志，`summary.json` 汇总整个面板。

创建一个可逐项检查的工作区：

```bash
python examples/recursive_learning/prepare.py ./digits-lab --method sft --policy self-use --seed 10
nanorsi run --workspace ./digits-lab
nanorsi freeze --workspace ./digits-lab --repeats 1
nanorsi final-test --workspace ./digits-lab
nanorsi report --workspace ./digits-lab --format html
nanorsi verify --workspace ./digits-lab
```

单个工作区演示的是机制。要判断递归复用是否带来额外收益，需要运行预算匹配的完整对照面板。

## 干预与对照

每种策略每轮都对相同的 1,074 个 TRAIN 样本评分。优先级课程使用指定改进器检查点的损失，提高损失最高四分之一样本的采样权重。SFT 保持各类别原有的经验采样占比；RL 和 LoRA 使用验证阶段选定并记录的全局优先级方案。

| 策略 | 哪个检查点评分 TRAIN 数据？ | 如何选择训练样本？ |
| --- | --- | --- |
| frozen | 每轮使用初始检查点 | 优先级固定为初始检查点给出的排序 |
| self-use | 最新被接受的检查点 | 接受训练结果后重新计算优先级 |
| uniform | 最新被接受的检查点，但刻意不使用评分 | 均匀采样 |
| random | 最新被接受的检查点，但刻意不使用评分 | 随机刷新重点样本，匹配数量和权重集中程度 |

所有策略都继续训练各自最新被接受的检查点。同一方法内，它们共享初始化、轮数、batch size、按尝试编号划分的随机数序列、TRAIN/验证数据、前向评分面板和验证机会。Uniform/random 的采样策略差异单独记录，不与通用递归/frozen 比较标识混淆。不声称优先级排序开销和进程运行时间完全相同。

每个候选按**验证集交叉熵**决定是否接受，准确率作为次要指标保留。每次尝试使用独立的随机种子，避免一个被拒绝的候选在下一次尝试中原样重放。报告分别记录实际尝试的更新数、样本数、评分工作量、失败尝试和选中检查点保留的训练步数；拒绝候选可能使保留步数不相等。

| 方法 | 轮数 | 每轮更新数 | Batch size | 学习率 | 优先级倍率 | 保持类别占比 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| SFT | 6 | 24 | 32 | 0.3 | 9 | 是 |
| REINFORCE | 6 | 8 | 32 | 0.3 | 3 | 否 |
| LoRA | 6 | 24 | 32 | 0.3 | 3 | 否 |

有效矩阵为 `W + A @ B`，三者形状分别为 65×10、65×4、4×10。SFT/RL 更新 W；LoRA 冻结 W，只更新 A/B。RL 梯度使用采样动作和标量奖励，但课程仍使用带标签的 TRAIN 损失，因此不是完全无标签的 RL 设置。

## 设置选择、留出数据与不确定性

数据为 UCI/scikit-learn 的 1,797 张光学手写数字子集。固定分层行划分（种子 20260912）包含 **1,074 张训练、359 张验证、364 张测试图像**，图像无重复，原始行 ID 无交叉。这是对原始 UCI 测试子集的新划分，**不是官方 UCI 基准划分**。数据没有书写者 ID，因此不能证明对未见书写者的泛化能力。见[数据来源与许可](data/README.md)。

两组仅使用验证集的预实验采用开发种子 0、1、2：先运行 24 个全局优先级配置，再运行相同的 24 个配置并加入类别占比归一化。[全部 48 个配置、576 条策略/种子试验记录](pilots/README.md)及源码和 CSV 证据均保留。强全局优先级经常使 frozen 对照弱于 uniform；设置没有仅按递归/frozen 差值大小挑选。选定设置的平均验证准确率也达到或超过了 uniform/random。所有开发实验均未评估确认实验的测试面板。

确认实验设置与种子在测试前锁定。全部 120 个工作区必须通过全局冻结检查，才允许第一次 final-test 调用。各方法的配对差值使用同一冻结测试面板。描述性 95% bootstrap 区间量化训练种子的波动；默认三个主要比较另有名义 Bonferroni 校正区间，用于预先声明的目标：观测平均提升至少 5 个百分点、校正区间下界为正、预算匹配证据完整。配对百分位 bootstrap 使用 10,000 次重采样，不提供有限样本下精确的家族错误率保证。缺失或失败尝试仍会显示，并阻止无保留的更新预算匹配成功结论。这些区间不衡量新数据集或新书写者的不确定性。

基于检查点的重加权与已有的[在线 batch 选择](https://arxiv.org/abs/1511.06343)和[优先级经验回放](https://arxiv.org/abs/1511.05952)相关。本例独立实现一个简单课程机制来检验递归复用，没有复现这些论文的完整系统，也没有借用其报告的收益。

## 反馈规模与工作量核算

`[evaluator].train_limit` 控制 TRAIN 反馈面板，已有 starter 的默认值仍为四。本研究将其设为完整 TRAIN 集。该设置不改变训练器接收哪些行。完整搜索额度为 `V + attempts × (min(train_limit, T) + 2V)`，其中 T/V 是 TRAIN/验证行数；最终测试 episode 单独计算。训练命令还有自己的时间与输出上限，episode 数本身不代表梯度更新数或计算量。

公开面板实际执行了 13,440 次更新、采样 430,080 个样本，选中检查点共保留 13,072 次更新。REINFORCE 的 frozen 与 self-use 每次实验都尝试 48 次更新，但平均保留的更新数为 24.0 与 47.2。因此，效果包含课程选择与验证集接受机制，并非在相同保留训练深度下比较课程质量。被拒绝候选消耗的工作量仍计入实际预算。公开证据来自核验过的本地日志，但导出本身未签名，不包含 HMAC 密钥或完整工作区；其校验和可检查内部一致性，不能独立证明原始执行的真实性。见[证据边界](../results/recursive-digits-v0.4.1/README.md#inspectable-evidence)。
