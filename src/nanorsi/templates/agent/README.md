# Agent runner improvement lab

This lab improves executable agent code in `target/agent/run.py`. The local agent
loads JSON data, filters rows, computes totals, and writes results by executing a
workflow. Its initial scheduling policy makes one pass through the supplied
steps. Ordered workflows work; other acyclic orders expose the missing planning
behavior without changing the tool implementations or task contract.

Configure your model, endpoint, and explicit credential file in `nanorsi.toml`.
Only code proposals call the configured model, including GLM when selected by the
operator. Task execution itself uses deterministic local tools, not model calls.
This is a small executable planning demonstration, not a broad agent benchmark.

The shared `_skills.py` runtime supplies the model bridge and proposal protocol.
The mutable runner retains both `task` and `propose` entry points. In a self-use
experiment (`experiment.arm = "self-use"`), an accepted runner is loaded again to
make the next proposal. The `runner_loaded` trace contains the SHA-256 hash of the
actual entry-point source for both task and proposal execution. Frozen mode uses
the baseline proposer entry point. Defaults compare baseline and candidate.

The fixed evaluator supplies four training, four validation, and four test
workflows from disjoint groups. Only training feedback contains expected outputs.
Candidate source changes are generated by the model from this feedback; no
prewritten scheduling patch is selected automatically.

Only `target/agent/run.py` is mutable. Keep the shared runtime, tools, workspace
path checks, and task/propose protocol intact. Candidate code runs as trusted
local Python with process limits; these limits are not a security sandbox.
